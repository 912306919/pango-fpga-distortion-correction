## 1. 改动内容

### 1.1 `distortion_map.v`
- 输出从整数改为 **Q12.4**（11 位整数 + 4 位小数）：
  - `u_source[14:0]`
  - `v_source[13:0]`
- `final_*_wide` 右移 28 位，并加 `2^27` 做 1/16 像素舍入。
- 边界判断改为 Q4：`0 <= q4 < IMG*16`。
- 保持原 7 级流水线。

### 1.2 `distortion_line_buffer.v`
- 从单数组改为 **4 bank**，按 `{v[0], u[0]}` 分 bank，每个 bank 是独立的简单双端口 RAM 子模块 `distortion_line_ram`。
- 一拍读出 2×2 四个像素，支持双线性。
- 行 tag/valid 在整行写完时才置有效；写入中的行不会被读出。
- 读地址按样本所属 bank 路由到对应 RAM；bank 选择打一拍后再做输出 mux，保证 RAM 数据与 bank 对齐。
- 边界：双线性取样时 `u+1`、`v+1` clamp 到 `IMG-1`；源坐标整体越出 1280×720 的像素由上层画黑边（见 1.4）。
- 缓存容量：64 行 × 1280 × 16bit = 160KB，DRM 占用 73/155（与基线一致）。

### 1.3 `bilinear_interp.v`（新增）
- RGB565 拆成 8 位，按 4 位小数权重做双线性，再打包回 RGB565。
- 权重和 256，`+128 >> 8` 四舍五入。
- 1 级流水；`NEAREST=1` 时旁路为 p00，用于 A/B。
- 顶层参数 `BILINEAR_NEAREST` 控制。

### 1.4 `hdmi_top.v`
- 接入 `distortion_map → distortion_line_buffer → bilinear_interp`。
- 单条矫正流水：`affine_map`(2) + `distortion_map`(7) + 行缓存(1) + 双线性(1) + 输出寄存(1) = **12 拍**。
- 显示时序管道为 **11 级移位 + always 末端输出寄存**，与 12 拍数据流水严格同拍，图像不平移。
- 原图/矫正共用 **一份 128 行** 环形源缓存：原图视图用全零畸变系数走同一条流水（数学上恒等），省掉第二份行缓存和 identity 请求管道。
- 越界处理：`distortion_map` 输出 `in_range`，源坐标落在 1280×720 之外的像素输出**黑边**，不再把边界行/列重复采样成拉伸模糊条带；图像内若行缓存未命中（理论上不发生）仍用同延迟原始像素兜底。
- `sync_vg` 的 `DISPLAY_LINE_DELAY` 为 **64**，源行窗口约 `y-63 ~ y+64`。
- 仿射范围：roll ±3.5°，tx ±600 像素，ty 每帧动态限幅 `50 - (640·sin|θ| + 360·(1-cosθ))` 像素，保证旋转+平移后源行仍落在窗口内。
- 增益 5 像素/度（`GAIN_Q16=3277`，已声明 signed）。上板实测方向：yaw 正→画面左移，pitch 正→画面上移（原始方向相反，故 `Y_INV=1'b1` 反相），roll 正→绕中心逆时针；如需再改方向，改 `X_INV`/`Y_INV` 即可。
- 新增参数 `BILINEAR_NEAREST`（默认 0）。

## 5. 已知限制

- 720P 下片上 BRAM 总量约 5.6 Mb，而一帧 1280×720×16b = 14.7 Mb，无法整帧缓存；本版用 128 行窗口（y-63~y+64），因此旋转只到 **±3.5°**（此时左右两端已占用约 40 行），ty 余量随角度减小。
- 真·任意角度（>5°）需要改成从 DDR3 分块/双 pass 反向取点（tile 架构），当前行缓存方案做不到。
- I/O 时序约束仍不完整（`cmos1_data`、HDMI 输出等未约束），这是原工程遗留问题，不影响本次功能验证，但正式提交前应补。
- 标定参数采用队友 **2026-10-27** 的新标定（同一 OV5640、同一对焦、1280×720）；换镜头/改对焦/改分辨率后必须重新标定。
- `BILINEAR_NEAREST=1` 的 A/B 版本未单独生成比特流；需要时改参数重新综合。
- IMU 零点只在复位后标定一次（30 帧跳过 + 128 帧静止平均 ≈ 5 s），没有运行中重标入口。6 轴 yaw 会缓慢漂移，长时间运行后残差 yaw 会变大；需要长期稳定时应改为「慢更新姿态基线」而不是一次性固定零点。

### 8.1 旧实现的问题

旧版是「固定 gamma=0.5 全量程曲线 + 按像素亮度混合」：

- 曲线固定、与场景无关，白天和夜里输出同一条曲线，谈不上「自适应」；
- 全量程 gamma 会把高光一起抬起来，正常光照下画面偏灰、通透度下降；
- 强光（过曝）场景完全没有处理手段 —— 而赛题明确要求覆盖「强光、夜间」。

### 8.2 新算法：两条半程曲线 + 场景自适应强度

| 曲线 | 定义 | 作用范围 |
|---|---|---|
| `lut_lift[ch]` | `ch<=176` 时 `176*(ch/176)^0.45`，`ch>176` 时保持原值 | 只抬暗部，176 以上高光恒等 |
| `lut_comp[ch]` | `ch<=96` 时保持原值，`ch>96` 时 `96+136*((ch-96)/159)^1.15`，**终点 232** | 只压高光，96 以下暗部恒等 |

> 强光曲线的终点是 **232 而不是 255**。第一版把端点钉在 255（`comp[255]=255`），导致
> 纯白像素 `d = 0`，无论强度多大都不变；而且为了让曲线回到 255，最后一段斜率变成 1.53
> （>1），高光反而被**拉伸**——这就是"强光看着没反应"的根因。改后会变成：全程斜率 ≤1，
> 连死白也能被压下来。

逐像素（R/G/B 共用同一强度 s，等价于按亮度整体缩放，不产生色偏）：

```
d   = (s>0 ? lut_lift[ch] : lut_comp[ch]) - ch
out = clamp(ch + (d * |s|) >> 8, 0, 255)
```

| 强度 | 含义 | 实测样例（ch → out） |
|---|---|---|
| `s = 0` | 位精确恒等 | 全部 65536 个码字 out == in |
| `s = +255` | 夜间强提亮 | 16→59、64→111、128→152、**176/200/230/255 保持不变** |
| `s = -255` | 强光压高光 | 16/32/64/96 保持不变、128→118、176→158、200→179、230→208、**255→232** |

帧级定档（每帧用上一帧统计重算一次）：

| tier | 条件 | s 目标 |
|---|---|---|
| 4 GLARE | 高光像素（y>215）占比 **≥ 5%** | -255（强光，优先级最高） |
| 0 NIGHT | 平均亮度 < 50 | +255（夜间） |
| 1 DIM | 平均亮度 < 90 | +170 |
| 2 NORMAL | 平均亮度 < **135** | 0（正常光照，恒等） |
| 3 BRIGHT | 平均亮度 < **170** | -170 |
| 4 GLARE | 其余 | -255（强光） |

阈值写成「整帧亮度和 vs `PIX_PER_FRAME × 平均亮度`」的常量比较，**全程无除法器、无乘法器**，
只有累加器与比较器。为避免档位在阈值附近来回跳，做了两层平滑：

1. **档位迟滞**：新档位要连续 **3 帧**都成立才真正切换（`TIER_HOLD`），屏幕读数和控制强度
   用的是同一个「确认后」的 `tier_next`，读数与实际强度永远一致；
2. **强度平滑**：s 每帧向目标逼近 1/8（720P@30 约 0.9 s 收敛），差量小于 8 时直接吸附到
   目标，保证 s 能精确等于 0 / ±255。

屏幕读数（`adv3_status_label`，位置 (24,56)，两行 64 像素高）：

| 行 | 内容 | 说明 |
|---|---|---|
| 第一行 | `NIGHT` / `DIM` / `NORMAL` / `BRIGHT` / `GLARE` | 当前档位 |
| 第二行 | `Y:128 G:05%` | 判档依据：平均亮度 / 高光占比 |

颜色：青=提亮、白=正常、橙=压暗。第二行的两个数字用来现场标定阈值（见 8.7）。

### 8.3 为什么高光占比阈值是 5%（2026-11-03 修正）

**现象**：上板后发现拿手电照镜头，读数一直是 `NORMAL`，而遮挡镜头变暗时档位正常变化。

**根因**：OV5640 默认开着自动曝光 —— `reg_config.v` 里写了 `0x3503 = 0x00`（AEC/AGC/AWB
全自动），而且整份配置**没有**写 `0x3501/0x3502`（曝光）或 `0x3508/0x3509`（增益）。
AEC 的作用就是把「整幅平均亮度」闭环压回它的目标值附近（实测稳定在 90~145）。
所以手电照上去时，传感器立刻降低曝光，平均值几乎不动，只有光斑被截断成 255 ——
**用平均亮度永远判不出强光**。旧阈值 20% 时，普通手电光斑只占画面 5%~15%，同样够不到。

| 场景 | 传感器行为 | FPGA 看到的平均亮度 | 旧判据结果 |
|---|---|---|---|
| 正常室内 | AEC 闭环 | 90~145 | NORMAL（合理） |
| 手电照一个点 | AEC 压低曝光，只有光斑截断 | 仍 90~145，`y>215` 占 5~15% | NORMAL ❌ |
| 捂住镜头 | AEC 到极限仍不够 | < 50 | NIGHT ✅ |

**修正**：强光判据改为以「被截断的高光面积」为主，阈值 20% → **5%**。
若现场发现正常光照下 `G` 读数就 ≥5%（例如窗外大逆光），说明 5% 偏敏感，把 `BR_GLARE`
改到 8~10% 即可 —— 屏幕第二行的 `G` 就是给这个标定用的。

**2026-11-03 追加**：实机上"橙色读数（BRIGHT/GLARE）"还是出现得太晚，把平均亮度门限
也下调了一档：`TH_NORM` 150 → **135**、`TH_BRIGHT` 190 → **170**。
副作用是：正常室内如果 `Y` 已经到 135 以上，会提前进 `BRIGHT` 并开始轻度压高光，
画面会略显发闷 —— 真出现就按屏幕上的 `Y` 把这两个常数微调回去
（`advanced_task3.v` 里两行 localparam）。

### 8.8 上板现象（位置 (24,56)，两行，只在 KEY2 进入时显示）

| 第一行读数 | 颜色 | 含义 | 画面表现 |
|---|---|---|---|
| `NIGHT` | 青 | 夜间（平均亮度 <50） | 暗部大幅提亮，高光不动 |
| `DIM` | 青 | 偏暗（<90） | 暗部中等提亮 |
| `NORMAL` | 白 | 正常（<135） | **画面完全不变**（位精确恒等） |
| `BRIGHT` | 橙 | 偏亮（<170） | 高光轻度压缩 |
| `GLARE` | 橙 | 强光（≥170 **或高光占比 ≥5%**） | 高光明显压回，死白也会下降 |

第二行是判档依据：`Y:128 G:05%`（平均亮度 / 高光占比，均为上一帧实测值）。

- 正常室内光照：读数 `NORMAL`，画面与基础任务**逐像素一致**；
- 遮住镜头 / 弱光：读数变 `DIM`、再变 `NIGHT`，画面约 0.9 s 内明显变亮；
- 拿手电照镜头：AEC 会把 `Y` 压在 90~145 不动，但 `G` 会明显上升；
  `G ≥ 5%` 即判 `GLARE`，最亮处从 255 压到约 232，死白区域出现层次。

### 8.9 已知限制

- 统计把黑边（源坐标越界输出的 0 像素）也算作暗像素，大角度旋转时黑边增大，
  会让平均亮度略微偏低（±5° 时黑边约 3.4%，偏低 4~6 个码值）；只在贴着阈值时才会
  影响分档。彻底解决需要给模块加一个 `in_range` 输入把黑边排除在统计外。
- 全场统一一条曲线，不做局部（分块）自适应；如需 CLAHE 级效果需要额外的行缓存开销。
- **强光只能靠"高光占比"判**：因为 OV5640 的 AEC 会把平均亮度闭环钉住（见 8.3）。
  如果演示时希望"手电一照画面真的过曝、压缩效果更夸张"，需要在高阶任务三模式下临时
  关掉 AEC（`0x3503 = 0x03` + 固定曝光 `0x3501/0x3502`），这要求把 `reg_config` 的
  上电一次性配置改成运行时可重下发，目前未实现。
- 平均亮度分档阈值（50/90/135/170）是经验值，没有在板子上逐档标定；
  建议用第二行的 `Y` 读数对照实际情况再微调一次。
